# PaRuX Release Security Review (gate SEC-001)

Date: 2026-11-09 (original read-only pass); remediation status and scanner results updated 2026-11-13
Reviewer: Claude (security-reviewer role), read-only pass
Repository state: branch `main`, HEAD `f420f347` plus uncommitted UI/test edits (not security relevant)

## Scope

In scope: the local ASP.NET Core "Core" server (`src/PaRuX.Server`), the WinUI desktop app services that execute
commands or drive the desktop (`src/PaRuX.App/Services`), the update helper (`src/PaRuX.UpdateHelper`), the Android
client (`src/PaRuX.Android`), the MSI project (`installer/PaRuX.Setup`), and tracked repository content.

Areas covered: Core exposure and auth, secrets, process execution, downloads/updates/archives, file access and
deletion, prompt-injection authority, plugins/MCP/connectors, Android client, dependency manifests.

## Method

Static review only. Nothing was built, run, launched or tested, no network was used, and no source or test file was
modified. Findings come from reading code paths and from `git grep` pattern searches over tracked files. Where a path
was read end to end the confidence is "confirmed"; where an effect depends on behavior I could not observe (browser
behavior, third-party binaries, runtime configuration) it is "suspected". No CVE lookup was done: dependency
vulnerability status needs `dotnet list package --vulnerable --include-transitive` (see Follow-ups).

## Verified controls

Core exposure and auth
- Kestrel binds loopback only (`Program.cs:36-37`); the LAN listener is opt-in, HTTPS only, and only for an address that is currently assigned and private (`Program.cs:39-43`, `RemoteAccessService.cs:52-61,348-374`; wildcard addresses are never selected).
- Non-loopback requests need a private source address, HTTPS, no `Origin` header, and a valid paired-device token unless completing pairing (`Program.cs:490-522`). Comparisons use `FixedTimeEquals`; device tokens are stored only as SHA-256 hashes; the raw token is returned once (`RemoteAccessService.cs:202-217`).
- The desktop token is random 256-bit, regenerated every start (`ServerState.cs:68`). API keys are limited to `/v1` and Ollama paths and are rechecked after in-flight admission (`Program.cs:535-586`).
- There is no CORS configuration anywhere in Core, so cross-origin browser calls fail preflight.
- Paired devices are default-deny with an exact-path allowlist and a second desktop-owner assertion on backup import (`PairedDeviceEndpointPolicy.cs`, `PairedDeviceAbuseMiddleware.cs`, `BackupImportGuardMiddleware.cs:41-48`). Desktop-only gates were present on MCP server management, runtime install/locate, remote config and pairing start, AI backend/cloud-fallback/API key/web-access/gateway settings, document output folder, game hooks, model deletion, adapter deletion, coding-task creation with workspace.
- Web access: PBKDF2 passphrase, lockout, HttpOnly/Secure/SameSite=Strict cookie, per-session CSRF token, CSP and no-referrer headers (`WebAccessEndpoints.cs`, `WebAccessService.cs`).

Secrets
- Credentials go through `SecretProtection` (DPAPI with per-purpose entropy on Windows, AES-GCM key file elsewhere): Hugging Face token, LoRA token, MCP credentials, remote provider and cloud fallback keys, IGDB/SteamGridDB keys, integration secrets, torrent recovery store. API keys are stored as hashes (`ApiKeyService.cs:222`).
- No `Log.Write` call that includes tokens, passphrases or prompt bodies was found; Android stores the pairing token in an AndroidKeyStore AES-GCM blob (`DeviceCredentialStore.kt`).
- `git grep` found no private keys, cloud/API token patterns, `.env`, `.pfx`, or personal absolute paths in tracked files.

Process execution
- Model-requested shell commands run in a Windows AppContainer with no network capability, sanitized environment, kill-on-close job object and no unsandboxed fallback (`WindowsCodingSandbox.cs:20-37,150-330`); a command preflight and denylist run first (`CodingAgentTools.cs:527-546`).
- File tools resolve against the workspace root and refuse symlinks/junctions in every path segment (`CodingAgentService.cs:2331-2356`). Host git is refused in worktrees whose `.git` link could have been altered by the sandbox, runs with `core.fsmonitor=false`, and agent diffs disable external diff and textconv (`CodingAgentTools.cs:604-612,747-780`).
- Computer Use launches only built-in apps or the user's configured allowlist by exact name, re-validates at execution, honors the Internet setting for browser opens and Gaming mode, denies password-like targets and requires confirmation for sensitive labels (`ComputerUseService.cs:105-255`, `ComputerUseSensitiveActionPolicy.cs`).
- Game launches pass only URIs PaRuX builds from discovered installs, or user-registered executables; hooks are off by default, `.exe` regular files only, bounded arguments and timeout (`ManualGameSessionService.cs:555-580`, `GameLaunchHooks.cs:90-99,167-181`).
- Automations can only create agent tasks; automation git uses the same worktree trust check (`AutomationEngine.cs:378-392`).

Downloads, updates, archives
- Updates require an RSA-SHA256 signed envelope against an embedded public key, an exact GitHub release URL, canonical version, package size/SHA-256, a strictly newer version, and re-verification of the copy staged under Program Files before `msiexec` (`SignedAppUpdateChannel.cs:65-140`, `UpdateHelper/Program.cs:95-170`).
- Managed runtime archives require a GitHub SHA-256 digest, exact byte count, trusted release host after redirects and a repository-bound URL (`RuntimeArtifactSecurityPolicy.cs`). The uv bootstrap is pinned to a SHA-256 (`ManagedPythonRuntime.cs:60-70`).
- Model downloads are limited to huggingface.co resolve URLs and an allowlisted transfer host set, with the hub token attached only to official hub hosts (`ModelDownloadService.cs:1441-1445,1943-1947,2408-2457`).
- `SafeArchiveExtractor` rejects rooted/drive/ADS paths, reserved names, symlink entries, traversal and reparse points in any ancestor, enforces a byte quota, and extracts via temp-then-rename (`SafeArchiveExtractor.cs:50-140`). Portable game ZIPs get entry-count, duplicate, symlink and expanded-size checks (`PortableGameInstallService.cs:183-215`). Backup import is flat-named, counted and decompression-budgeted.
- Torrent: magnet and `.torrent` sources are strictly validated; the external client adapter is off until configured; the embedded engine disables port forwarding and LAN discovery and is cancelled by Gaming mode (`GameDownloadSourceValidator.cs`, `EmbeddedTorrentTransport.cs`).
- Web search/fetch connects only to DNS-validated public addresses through a `ConnectCallback`, no proxy, bounded redirects and bodies (`WebSearchService.cs:25-70`), and labels fetched text as untrusted.

File access
- RAG ingestion blocks credential stores, key files, browser profiles, wallets, PaRuX's own data and system folders, requires consent for drive roots/profile/AppData, and skips reparse points (`KnowledgeSecurity.cs:14-125`, `KnowledgeIndex.cs:318`). Index and database files are restricted to the current user.
- Destructive operations (model, adapter, game library entry, backup safety snapshots, MCP server removal) are desktop-owner only; Epic/Steam/GOG, linked Ollama/LM Studio models are not deleted.

Plugins, MCP, connectors
- Stdio MCP servers can be added only by the desktop owner; HTTP MCP servers must be https unless loopback/private, URLs cannot carry credentials or query strings, credentials are stored encrypted and never read back (`McpServerEndpointPolicy.cs`, `Program.cs:1510-1514`). MCP tools reach the coding agent only through the `mcp.external` capability, server identity is kept, reserved action names and lookalike names are refused (`AgentMcpToolAuthority.cs`). The Core `/mcp` endpoint exposes read-only memory/document/skill search behind the normal auth.
- Plugin/import automations can be created disabled; skill permissions can be changed only by the desktop owner (`Program.cs:1798-1809`).

Android
- `allowBackup=false`, `usesCleartextTraffic=false`, one exported activity (launcher and SEND filters), FileProvider not exported and scoped to `shared-media/` only; no accessibility service. OkHttp client trusts only the fingerprint pinned at pairing (no system CAs), disables redirects and refuses desktop-only endpoints client side (`PinnedTrust.kt`, `PaRuXHttpClient.kt`). Release signing secrets come from properties, not the repo.
