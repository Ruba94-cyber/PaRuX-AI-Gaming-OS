# Reviewed inventory of every process launch (new Process{...} / Process.Start(...)) under src/PaRuX.Server.
# Enforced by GamingHardOffProcessLaunchInventoryTests: a new launch site, a changed count or a missing/blank reason fails the test.
# A reviewer adding a launch must state HOW Gaming Mode hard-off covers it (or why it is not an AI child) in the last column.
#
# Format:  relative path | launch-site count | class | launching method(s) | gate | how it is covered
# Classes:
#   STOPPED-BY-HARDOFF  the child is registered with a Gaming boundary (GamingChildScope / SpeechProcessAdmission /
#                       LocalAiProcessManager StopAll): refused while Gaming is active, killed with exit confirmation on a Gaming start.
#   CALLER-GATED        the launch itself is not registered, but every caller refuses while Gaming is active and runs the child
#                       under a token the Gaming transition cancels (GamingHardOffWatch / GamingCancellationToken), killing it.
#   Gate column: '-' means the launching method's own body must show a Gaming mechanism (comments/strings do not count);
#   'File.cs#Method[;File2.cs#Method2]' names the gating caller method(s), which the test finds and checks.
#   NOT-AI              a short bounded tool/OS probe, not a PaRuX AI child, uses no model and no GPU inference.
#   GAMING-FEATURE      part of the game/launcher integration itself (launching or suspending the game), not an AI child.
#
